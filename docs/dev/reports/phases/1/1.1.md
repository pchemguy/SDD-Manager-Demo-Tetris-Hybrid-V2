# Milestone 1.1 Report — Falling pieces and locking prototype

## 1. Overview and Scope

Milestone 1.1 (*Falling pieces and locking*, tasks `T-001` through `T-008`) delivers the foundational browser-based TypeScript Tetris prototype under SDD Manager workflows on working branch `phase/1-classic-game`.

The delivered capabilities establish:

- Isolated browser development environment conforming to `BROWSER_DEV_POLICY.md` (Chromium and Firefox provisioned in `.browsers/`).
- Strict TypeScript configuration hierarchy separating engine types (`tsconfig.engine.json` with no DOM/Node globals) from application and test scopes (`tsconfig.app.json`, `tsconfig.test.json`).
- Seven-tetromino geometry tables, standard spawn coordinates, 0-offset quarter-turn rotations, and legal board placement/locking under `G-BOARD` and `G-ROTATE`.
- Canonical 7-bag randomizer consuming exactly 6 draws per bag with atomic error failure and deterministic queue maintenance under `G-SEQUENCE`.
- Central `GameSession` coordinator managing lifecycle (`ready`, `running`, `paused`, `gameOver`), action validation, duration-bounded time advancement, and detached immutable snapshots under `S-API`, `S-DATA`, and `S-DETERMINISM`.
- Chronological gravity and full-interval normal locking under `G-TIME`, including grounding detection, lock timer deadline preservation, airborne timer resets, same-timestamp lock precedence, and atomic random-dependent timed spawn failure.
- Pure Canvas and HTML presentation layer (`CanvasRenderer`, `HtmlView`) rendering board, active piece, status overlays, preview, and statistics from snapshots under `B-VIEW`.
- Browser input and clock adapters (`AnimationClock`, `KeyboardInputAdapter`, `GameController`) driving the interactive prototype with native controls and monotonic frame delivery under `B-CONTROLS` and `B-TIME`.

Modern placement enhancements (nonzero wall kicks, hard drop, hold piece exchange, and ghost projection) remain explicitly scheduled in Phase 2 per `PLAN.md`. Progression features (row clearing, scoring, and level advancement) are scheduled in Milestone 1.2 (`T-009`–`T-014`).

## 4. Code Review and Architectural Findings

A comprehensive review of integrated code was performed separately from test execution:

1. **Separation of Concerns:**
   - The engine (`src/engine/`) has zero dependencies on browser APIs, Canvas, or clock globals (`window`, `Date`, `requestAnimationFrame`). Time is strictly delivered via `advance(elapsedMs)`.
   - The UI presentation (`src/ui/`) is read-only with respect to engine state; it reads detached immutable snapshots without computing placement or mutating live state.
   - The browser adapters (`src/browser/`) manage environment-specific bindings (animation frames and DOM keyboard events) and delegate all domain rules to the engine.

2. **Locking and Timing Semantics:**
   - Grounded detection accurately checks `!isLegalPlacement(board, piece, rotation, y + 1)`.
   - The lock timer is initialized to 0 on first landing and preserved across legal horizontal moves or rotations while remaining on support.
   - Stepping or rotating off support into empty space correctly clears the lock timer, and subsequent re-landing initiates a fresh full interval.
   - When a lock deadline and gravity tick coincide, lock takes precedence per `G-TIME`.
   - Residual advance duration is correctly passed to the newly spawned active piece.

3. **Resolved Inspection Items:**
   - Read-only preview: `PieceSequence.peekNext()` was verified to never trigger bag refill draws on read, satisfying `G-SEQUENCE` and `S-DATA`.
   - Error handling: Injected random errors during timed spawn preserve the locked board and leave `active: null`, avoiding stale or half-spawned object corruption.
   - Focus management: Canvas element is explicitly focusable (`tabindex="0"`) with visible focus outlines and click-to-focus behavior per `B-CONTROLS`.

## 6. Demonstration and Usability Evidence

- A user can open the application, view the initial ready playfield with stats, and start play with the native Start button or Enter key.
- While running, the falling piece descends at level-1 gravity (1 row per 1000 ms), moves left/right, rotates clockwise/counterclockwise, and soft-drops.
- Upon hitting the floor or locked stack, the piece remains active for a 1000 ms landing delay. Repositioning on support maintains the deadline; stepping off support resets it.
- At the lock deadline, the piece merges into the board, and the next piece spawns from the 7-bag preview.
- Pausing via button or P/Escape freezes time; resuming continues smoothly. Restarting via button or R immediately resets the session to a fresh active piece.
- Building the stack up to the spawn area triggers game over, freezing play and retaining final totals on screen.
